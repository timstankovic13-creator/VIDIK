# VIDIK Municipal Reference Data

This directory contains controlled reference-data artifacts and fixtures. It registers the first high-value Canadian municipal reference sources. Authoritative upstream datasets must be imported through `scripts/municipal-reference-pack.js`; raw downloads are not treated as decision-driving evidence merely because they exist locally.

## Priority datasets

1. **Municipal spine:** Statistics Canada 98-10-0002-02 — Census municipal population, dwellings, geography, land area, density and ranks for census subdivisions/municipalities.
2. **Annual population:** Statistics Canada 17-10-0155-01 — annual July 1 population estimates by census subdivision using 2021 boundaries.
3. **Public safety:** Statistics Canada 35-10-0077-01 — municipal police personnel, authorized strength, rates, hirings/departures, retirement eligibility and selected crime statistics.
4. **Census Profile:** Statistics Canada 2021 Census Profile — demographic/socioeconomic baseline.

## Why both census and estimates?

The 2021 Census provides a stable benchmark; the annual population-estimate series provides a more current municipal population context. They must remain separate evidence series rather than being blended without explicit derivation.

## Required validation

Every full import must pass CSV/schema validation, CSD identifier validation, duplicate detection, numeric/range validation, suppression/missing-value handling, reconciliation to the WUP municipal spine, deterministic normalization, source/output hashing, and provenance generation.

## Current status

The repository contains a real Ottawa source-format fixture and automated ETL validation. Full upstream national extracts are intentionally generated by the importer from authoritative downloaded/API artifacts rather than committed blindly. Source registration is deliberate so eventual extracts can be generated reproducibly and hashed.

## Ingestion boundary

Generate compact extracts keyed to the VIDIK municipal identity and WUP city spine, attach provenance and SHA-256 hashes, then run reconciliation before the extract becomes decision-driving.
