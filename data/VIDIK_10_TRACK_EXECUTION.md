# VIDIK — 10-Track High-Impact Execution

This is the active work package for the ten highest-impact tracks identified after RC4.

1. **$5M Public Safety Decision Lab** — implemented as a synthetic-only allocation engine with 10 scenarios; no production effect/ROI/recommendation promotion.
2. **Decision Benchmark v2** — 10 known-answer scenarios now; expand to 20–30 with adversarial causal/evidence cases before CI certification.
3. **Real evidence acquisition** — MSE pipeline specifies exact claim-level requests and ranks 009/010 first, then 014, then 006; real authorization/data remain external.
4. **Customer lifecycle** — auditable Question→Scope→Evidence→Eligibility→Allocation→Human Decision→Implementation→Review→Outcome→Recalibration contract documented.
5. **Decision red team** — hostile evidence, causal, numeric, integrity and override attacks defined as acceptance cases.
6. **Acquisition automation** — pipeline contract converts blocked claims into machine-readable MSE/request/validation states; production connectors remain external-data dependent.
7. **Cross-city transportability** — Ottawa/Toronto/Melbourne adapter matrix established; city-specific evidence cannot silently transfer.
8. **VIDIK value benchmark** — paired conventional-vs-VIDIK metrics defined for time, evidence gaps, refusals, opportunity cost, sensitivity and auditability.
9. **Demo package** — five-minute proof sequence defined around the $5M lab, evidence lineage, stress testing, lifecycle and refusal boundary.
10. **October release gate** — offline certification now; targeted CI first when Actions capacity returns, then regression only if justified.

## Definition of done
All offline artifacts are committed and internally testable without GitHub Actions. Real-world causal recommendations remain blocked until the existing experiment gates pass with authorized marginal exposure, admissible evidence, defensible counterfactual and measurement readiness.
