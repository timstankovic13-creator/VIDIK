# VIDIK Procurement Evidence Index

Use this index to assemble a municipality-specific procurement package.

## Product
- [ ] Product overview and intended use.
- [ ] System architecture/data-flow diagram.
- [ ] Decision Object and audit specification.
- [ ] Evidence/provenance specification.
- [ ] Outcome-learning and recalibration specification.

## Security
- [ ] Security baseline: `docs/SECURITY_BASELINE.md`.
- [ ] Current dependency inventory.
- [ ] Vulnerability scan results.
- [ ] Security assessment / penetration test when required.
- [ ] Incident response plan.
- [ ] Business continuity/disaster recovery plan.
- [ ] Backup/restore evidence.

## Privacy
- [ ] Privacy/data inventory.
- [ ] Data-flow map.
- [ ] Retention/deletion schedule.
- [ ] Subprocessor inventory.
- [ ] Municipality-specific PIA package: `docs/PRIVACY_PIA_READINESS.md`.
- [ ] Data-processing/information-sharing agreement as applicable.

## Governance
- [ ] Human accountability statement.
- [ ] Model/evidence change-control procedure.
- [ ] Recalibration approval process.
- [ ] Failure/incident registry procedure.
- [ ] Accessibility review.
- [ ] Records-management requirements.

## Procurement / commercial
- [ ] Legal entity and ownership documents.
- [ ] IP ownership/assignment records.
- [ ] Insurance appropriate to the contract.
- [ ] Service/support levels.
- [ ] Pricing and implementation statement of work.
- [ ] Contractual liability/indemnity terms.
- [ ] Exit/data-portability plan.

## Validation evidence
- [ ] Automated test results for the current release.
- [ ] Municipal adapter/ETL validation.
- [ ] End-to-end lifecycle acceptance.
- [ ] Retrospective reconstruction or shadow-decision evidence.
- [ ] Live-pilot acceptance plan and measurable outcome definitions.

## Claim discipline
Every external claim must identify whether it is based on validation fixtures, retrospective analysis, shadow decisions, or live municipal outcomes. Do not describe synthetic/validation outcomes as municipal impact.
